## 1. 서론

### 1.1 문서 목적 및 범위

본 문서의 목적은 소프트웨어공학 과목 프로젝트로 진행하는 **에어 드라이브(Air Drive)** — 경량화된 팀 협업을 위한 분산 파일 관리 및 히스토리 추적 시스템 — 에 대한 테스트를 수행하고 그 결과를 나타내는 데에 있다. 본 문서에서는 프로젝트의 테스트 기준, 테스트 범위, 테스트 케이스와 테스트 결과를 명시한다.

> 본 프로젝트는 현재 설계 단계로, 실제 구현 전이다. 따라서 본 문서는 **테스트 디자인(설계)** 을 중심으로 작성하며, 6장의 테스트 결과는 설계 단계에서의 **예상 결과**를 기준으로 작성한다. 추후 구현이 완료되면 실제 테스트 수행 결과로 갱신할 예정이다.

### 1.2 프로젝트 개요

에어 드라이브는 사용자가 웹 브라우저만으로 파일을 업로드·다운로드·검색·공유할 수 있고, 파일별 버전 관리와 댓글, 활동 로그를 통해 팀의 협업 히스토리를 투명하게 추적할 수 있는 경량 웹 스토리지 시스템이다.

### 1.3 용어 정의

| 용어 | 설명 |
|:---|:---|
| 블랙박스 테스트 | 시스템 내부 구조를 모르는 상태에서 입력과 출력만으로 기능을 검증하는 테스트 기법 |
| 버전 제어 | 파일의 변경 이력을 관리하고, 이전 상태로 복원할 수 있는 기능 |
| 시간 제한부 링크 | 일정 시간이 지나면 자동으로 만료되는 임시 공유 URL |
| 활동 로그 | 파일의 업로드, 수정, 다운로드 등 사용자 행동 기록 |

### 1.4 참조 문서

## 2. 테스트 개요

### 2.1 테스트 범위

테스트는 시스템 내부를 모른다는 가정 하에 **블랙박스 테스트**로 이루어진다. 테스트의 범위는 아래와 같다.

| 범위 | 내용 |
|:---|:---|
| Web 기반 시스템 | Ⅰ. 브라우저/서버사이드 동작 정확성 확인<br>Ⅱ. 요구사항 충족 확인 |
| 파일 저장소 (Storage) | Ⅰ. 파일 업로드/다운로드 시 데이터 무결성 확인<br>Ⅱ. 버전 관리 데이터 정합성 확인 |
| Database | Ⅰ. 사용자/파일/댓글/로그 데이터 입출력 확인<br>Ⅱ. 공유 링크 만료 처리 확인 |

### 2.2 테스트 항목 및 통과 기준

#### 기능별 테스트 항목 및 통과 기준

| 기능 | 테스트 항목 | 통과 기준 |
|:---|:---|:---|
| 회원가입 기능 | 아이디(이메일)/비밀번호 유효성 검증 | 형식이 올바르고 중복되지 않은 정보만 가입에 성공한다. |
| 로그인 기능 | 회원 정보 검증 | 올바른 회원 정보만 로그인에 성공한다. |
| 파일 업로드 기능 | 파일 저장 및 버전 처리 | 정상 파일은 업로드에 성공하고, 동일 파일명 재업로드 시 이전 버전이 보존된다. |
| 파일 다운로드 기능 | 파일 다운로드 처리 | 존재하는 파일은 정상 다운로드되고, 삭제된 파일은 다운로드가 차단된다. |
| 폴더 관리 기능 | 폴더 생성 및 파일 이동 | 폴더가 정상 생성되고 파일이 지정한 폴더로 이동된다. |
| 공유 링크 기능 | 링크 생성 및 만료 처리 | 설정한 유효 시간 내에는 링크로 접근이 가능하고, 만료 후에는 접근이 차단된다. |
| 파일 검색 기능 | 키워드 기반 검색 | 키워드와 일치하는 파일이 정확히 표시되고, 결과가 없을 경우 안내 문구가 출력된다. |
| 댓글 기능 | 댓글 작성/검증 | 정상적인 댓글은 작성자/시간과 함께 저장되고, 공란 댓글은 등록이 차단된다. |
| 활동 로그 기능 | 이벤트 기록 및 필터링 | 업로드/다운로드 이벤트가 실시간으로 기록되고, 파일별 필터링이 정상 동작한다. |
| 버전 관리 기능 | 이전 버전 조회 및 복원 | 버전 목록이 정확히 표시되고, 복원 시 선택한 버전의 내용으로 교체된다. |

#### 비기능별 테스트 항목 및 통과 기준

| 항목 | 통과 기준 |
|:---|:---|
| 브라우저 호환 테스트 | 여러 브라우저(Chrome, Edge, Safari)에서 시스템이 동일하게 동작한다. |
| 검색 성능 테스트 | 검색 결과가 2초 이내에 출력된다. |
| 보안 테스트 | 로그인하지 않은 사용자는 파일 업로드/다운로드/공유 기능을 이용할 수 없다. |

## 3. 테스트 케이스

### 3.1 테스트 케이스 선정

테스트 케이스는 2.2의 기능별/비기능별 테스트 항목에 따라 선정하였으며, 블랙박스 테스트 기법을 기반으로 시스템 내부 구조를 확인하지 않는 **사용자 시점**의 테스트 케이스 선정에 중점을 둔다. 3.3에서 기능별 테스트 케이스 목록을 나열한다.

### 3.2 테스트 케이스 유형

테스트 케이스 유형은 다음과 같다.

- 회원가입/로그인을 위한 **문자열 입력 테스트 케이스**
- 파일 업로드/다운로드/검색/공유 등 **기능 동작 테스트 케이스**
- 버전 관리, 활동 로그 등 **데이터 정합성 확인 테스트 케이스**
- 브라우저 환경에 따른 **호환성 테스트 케이스**
- 비인가 접근에 대한 **보안 테스트 케이스**

## 4. 테스트 예외사항

| 중단 기준 | 재개 조건 |
|:---|:---|
| 시스템이 정의된 입력 형식과 다른 입력을 받았을 때 | 입력을 중단하고, 기존 데이터를 유지한 상태로 시스템을 재개한다. |
| 파일 업로드 중 네트워크가 단절되었을 때 | 업로드를 중단하고, 이전에 저장된 버전을 그대로 유지한 상태로 재개한다. |

## 5. 테스트 환경

### 5.1 테스트 환경 구성도

```
[ Test Client 1 ]            [ Test Client 2 ]
   (Web Browser)                 (Web Browser)
        │                              │
        └─────────────┬───────────────┘
                       │
                  [ Air Drive 서버 ]
                       │
                ┌──────┴──────┐
                │             │
          [ 파일 스토리지 ]  [ Database ]
```

| 구성 요소 | 설명 |
|:---|:---|
| Test Client 1, 2 | Chrome, Edge, Safari 등 브라우저를 통해 Air Drive 웹 시스템에 접속하는 테스트 단말 |
| Air Drive 서버 | 인증, 파일 업로드/다운로드, 검색, 공유 링크, 활동 로그 등 핵심 로직을 처리하는 서버 |
| 파일 스토리지 | 업로드된 파일 및 버전 데이터를 저장하는 저장소 |
| Database | 사용자, 파일 메타데이터, 댓글, 공유 링크, 활동 로그 정보를 저장 |
